## Portfolio direction

The portfolio should help a business owner understand what Sean builds, see real examples and find a clear way to start a conversation. Write about the work in familiar terms. Keep the full offer open, from one useful tool to a larger system delivered in stages.

| Page | Main job |
| --- | --- |
| Home | Introduce the service and show three concrete examples |
| Work | Let visitors choose a project |
| Project pages | Explain the requirement, what was built and the relevant screens |
| Services | Describe work Sean can take on, with contracting examples |
| Process | Explain scope, development, review, delivery and support |
| About | Introduce Sean and his verified experience |
| Contact | Make it easy to describe an idea or a problem |

Use these names and labels consistently:

| Public name | Type label | Route | Preview link |
| --- | --- | --- | --- |
| Plumbing Track console | Client operations software | /work/plumbing-track-console | View project |
| Fleet dispatch demo | Development demo | /work/fleet-platform | View demo details |
| Plumbing Track website | Client website | /work/plumbing-track-website | View project |

Keep “Development demo · Sample data” visible on the Fleet preview. Use “Working development demo using sample data” at the start of its project page. Repository and asset folder names can stay unchanged.

Use **Start a project** for the header and homepage's main contact button. Use **Start a conversation** for closing contact buttons. Both lead to /contact. **About Sean** leads to /about; **How I work** leads to /process. Use quiet text links for related projects.

Use sentence case for public headings and buttons. Keep the current brand treatment and short category labels. The copy plan's recommended homepage heading is “Software built around your business.” Its opening sentence remains “I build practical software around the way your business works, and the places where it could work better.”

Each document has a separate responsibility. The copy plan owns wording and section order. The layout plan owns image treatment and visual rules. Evidence notes own factual support. If wording differs between plans, use the copy plan. Evidence limits always apply.

## Historical material

[thesis.txt](thesis.txt), [graphify-note.txt](graphify-note.txt), the generated reports under graph/ and graph-code/, and images under ui/ record earlier research and designs. They are background, not the current website brief.

The old dark architectural hero, Cormorant Garamond and Outfit pairing, contact-card-only route, and sticky page transitions are not part of this portfolio plan. Preserve the historical record without taking its old instructions as current requirements.

The current design uses the cream palette, Barlow Condensed, IBM Plex Sans and IBM Plex Mono described in the layout plan. The current contact plan retains the inquiry form and email address. A broader digital business-card feature would need its own later decision.
